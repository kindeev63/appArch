Автоматические тесты для них реализованы в [scenarios_test.go](file:///home/knomster/Documents/CU/appArch/applications-architecture/week-02/code/scenarios_test.go).

## 1. Сценарий: Создание студента
- **Дано:** Корректный идентификатор `"student-001"` и непустое имя студента `"Иван Иванов"`.
- **Когда:** Вызывается фабричный метод создания студента `NewStudent("student-001", "Иван Иванов")`.
- **Тогда:** Студент успешно создан (`err == nil`); геттеры возвращают переданные значения (`ID() == "student-001"`, `Name() == "Иван Иванов"`); список курсов пуст (`len(CourseIDs()) == 0`); `IsEnrolled` возвращает `false`.
- **Rules:** Правило 1 (неизменяемость и валидация идентификатора при создании).

## 2. Сценарий: Создание учителя
- **Дано:** Корректный идентификатор `"teacher-101"` и непустое имя преподавателя `"Алексей Преподаватель"`.
- **Когда:** Вызывается фабричный метод создания преподавателя `NewTeacher("teacher-101", "Алексей Преподаватель")`.
- **Тогда:** Преподаватель успешно создан (`err == nil`); геттеры возвращают переданные значения (`ID() == "teacher-101"`, `Name() == "Алексей Преподаватель"`); список назначенных курсов пуст (`len(CourseIDs()) == 0`); `IsAssignedTo` возвращает `false`.
- **Rules:** Правило 1 (неизменяемость и валидация идентификатора при создании).

## 3. Сценарий: Создание задания учителем
- **Дано:** Преподаватель `"teacher-101"`, назначенный на курс `"course-arch-101"`; параметры задания: ID `"assign-301"`, название `"Проектирование микросервисов"`, дедлайн, разрешённые расширения `[".pdf", ".zip"]`, макс. размер 10 МБ.
- **Когда:** Создаётся задание `NewAssignment(...)` и публикуется преподавателем вызовом `assignment.Publish()`.
- **Тогда:** Задание успешно создано и опубликовано; статус равен `AssignmentStatusPublished`; `TeacherID()` совпадает с учителем, `CourseID()` — с курсом; расширения нормализованы и разрешены (`IsExtensionAllowed(".pdf") == true`); `MaxFileSize() == 10_000_000`.
- **Rules:** Правило 1 (неизменяемость связей), Правило 2 (статус публикации), Правило 4 (лимиты файлов).

## 4. Сценарий: Сабмит студентом файла по заданию через сабмишин
- **Дано:** Опубликованное задание курса `"course-arch-101"`; студент, записанный на этот курс; черновик отправки `NewSubmission("sub-401", assignment.ID(), student.ID())`; валидный файл `report.pdf` (500 КБ); время отправки до дедлайна (за 2 часа).
- **Когда:** Студент вызывает `sub.Submit(assignment, student, file, submitTime)`.
- **Тогда:** Отправка успешно принята (`err == nil`); статус `SubmissionStatusSubmitted`; `File()` возвращает принятый файл; `SubmittedAt()` фиксирует точное переданное время сдачи.
- **Rules:** Правило 2 (студент курса и опубликованное задание), Правило 3 (сдача до дедлайна), Правило 4 (валидный файл), Правило 5 (фиксация времени отправки).

## 5. Сценарий: Сабмит вторым студентом файла за первого студента
- **Дано:** Опубликованное задание курса; черновик отправки создан для первого студента (`"student-001"`); второй студент (`"student-002"`), также записанный на этот курс; валидный файл; время до дедлайна.
- **Когда:** Второй студент пытается сдать файл в чужую отправку: `sub.Submit(assignment, student2, file, submitTime)`.
- **Тогда:** Отказ с ошибкой `ErrStudentMismatch`. Состояние отправки полностью сохранено без изменений: статус остаётся `SubmissionStatusDraft`, файл `nil`, `SubmittedAt` нулевое.
- **Rules:** Правило 7 (принадлежность отправки студенту), Правило 10 (атомарность и отсутствие частичного изменения состояния).

---

## 6. Сценарий: Сабмит вне дедлайна
- **Дано:** Опубликованное задание с дедлайном 18:00; записанный студент; черновик отправки; валидный файл; время отправки строго после дедлайна (`дедлайн + 1 сек`).
- **Когда:** Студент пытается отправить файл: `sub.Submit(assignment, student, file, deadline.Add(1*time.Second))`.
- **Тогда:** Отказ с ошибкой `ErrDeadlinePassed`. Состояние отправки не меняется: статус `SubmissionStatusDraft`, файл `nil`, `SubmittedAt` нулевое.
- **Rules:** Правило 3 (дедлайн сдачи), Правило 10 (отказ без изменения состояния модели).

## 7. Сценарий: Сабмит по левому курсу
- **Дано:** Опубликованное задание курса А (`"course-arch-101"`); студент, записанный ТОЛЬКО на курс Б (`"course-history-202"`), но не на курс А; черновик отправки; валидный файл; время до дедлайна.
- **Когда:** Студент пытается сдать работу по заданию курса А: `sub.Submit(assignment, otherStudent, file, submitTime)`.
- **Тогда:** Отказ с ошибкой `ErrStudentNotEnrolled`. Состояние отправки не меняется: статус `SubmissionStatusDraft`, файл `nil`, `SubmittedAt` нулевое.
- **Rules:** Правило 2 (сдача только по заданию курса студента), Правило 10 (отказ без изменения состояния).

---

## 8. Сценарий: Сабмит с пустым файлом
- **Дано:** Опубликованное задание курса, записанный студент, черновик отправки, время до дедлайна.
- **Когда:**
  - 8.1. Попытка сдать `nil` вместо файла: `sub.Submit(assignment, student, nil, submitTime)`.
  - 8.2. Попытка создать Value Object `WorkFile` с размером 0 байт: `NewWorkFile("empty.pdf", 0, "storage-zero")`.
- **Тогда:**
  - В 8.1: отказ с ошибкой `ErrFileRequired`. Состояние отправки не меняется: статус `SubmissionStatusDraft`, файл `nil`, `SubmittedAt` нулевое.
  - В 8.2: конструктор завершается ошибкой `ErrInvalidFileSize`, объект файла не создаётся (`file == nil`).
- **Rules:** Правило 4 (файл работы обязателен и непуст), Правило 10 (атомарность).

## 9. Сценарий: Сабмит с файлом, нарушающим расширение
- **Дано:** Опубликованное задание с разрешёнными расширениями `[".pdf", ".zip"]`; записанный студент; файл `malware.exe` с расширением `.exe`; черновик отправки; время до дедлайна.
- **Когда:** Студент вызывает `sub.Submit(assignment, student, invalidExtFile, submitTime)`.
- **Тогда:** Отказ с ошибкой `ErrExtensionNotAllowed`. Состояние отправки не меняется: статус `SubmissionStatusDraft`, файл `nil`, `SubmittedAt` нулевое.
- **Rules:** Правило 4 (валидация разрешённого расширения), Правило 10 (отказ без изменения состояния).

---

## 10. Сценарий: Сабмит с отрицательным сайзом
- **Дано:** Параметры файла с размером `-1024` байт; черновик отправки студента по опубликованному заданию.
- **Когда:** Попытка сконструировать `WorkFile("corrupt.pdf", -1024, "blob-neg")`.
- **Тогда:** Фабричный метод возвращает отказ `ErrInvalidFileSize`, объект не создаётся (`file == nil`). Передать такой файл в отправку невозможно, черновик отправки остаётся нетронутым (`Draft`, `file == nil`).
- **Rules:** Правило 4 (размер файла строго положителен), Правило 10 (отказ при создании некорректного объекта).

---

## 11. Сценарий: Сабмит с сайзом сверх лимита
- **Дано:** Опубликованное задание с лимитом размера 5_000_000 байт (5 МБ); записанный студент; черновик отправки; файл размером на 1 байт больше лимита (`5_000_001` байт); время до дедлайна.
- **Когда:** Студент вызывает `sub.Submit(assignment, student, oversizedFile, submitTime)`.
- **Тогда:** Отказ с ошибкой `ErrFileSizeExceeded`. Состояние отправки не меняется: статус `SubmissionStatusDraft`, файл `nil`, `SubmittedAt` нулевое.
- **Rules:** Правило 4 (размер файла не превышает лимит задания), Правило 10 (состояние после отказа неизменно).
